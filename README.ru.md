# e4steam для Horizon — играть в свой LAN-мир с друзьями из Steam

[English](README.md) · **Русский**

e4steam даёт доступ к миру Minecraft, который ты уже открыл **по LAN**, друзьям из Steam — через
одноранговую сеть Steam. Без проброса портов, без белого IP, без арендованного сервера: друзья
заходят так, как заходят в любую Steam-лобби, а игровой трафик идёт напрямую с их компьютера на
твой.

Мод говорит по тому же wire-протоколу, что и Java-мод
[e4steam](https://github.com/Kamilhik/e4steam) (`E4ST` v4), поэтому друг с Java-модом на NeoForge
или Fabric может зайти в твой мир на Horizon, и ты — в его.

**Два способа запуска, один движок:**

| | Как работает | Чем управляешь |
|---|---|---|
| **Нативный мод** (`horizon-mod/`) | часть игры; собирает Horizon | **Esc → Options → Mods → e4steam → Settings** — страница кнопок; `/steam …` в чате тоже работает |
| **Sidecar** (`cli/`, `e4steam-rs.exe`) | консольное окно рядом с любой сборкой Horizon | в этой консоли: `e4steam-rs.exe host` |

Запускать их нужно **по одному**: один Steam-аккаунт не держит два контекста Steamworks, и оба
претендуют на один канал лобби.

> ### Прочитай перед установкой
> Это мод сообщества, а не официальный мод Horizon, и листинг в реестре Horizon — это проверка
> полноты и отсутствия явного вреда, а не рекомендация и не аудит безопасности.
>
> Нативные моды — это Rust, скомпилированный вместе с игрой. Они работают **с тем же доступом к
> твоему компьютеру, что и сама Minecraft**: без песочницы и без запросов разрешений. Ставь их
> только из источников, которым доверяешь, и, если можешь, читай код. Этот проект поставляется
> **без каких-либо гарантий**, как и сказано в Apache-2.0.

## Что нужно

| | |
|---|---|
| Steam | клиент запущен и ты в нём залогинен |
| Horizon | Nightly-сборка, закреплённая модом, — см. [Закреплённые версии](#закреплённые-версии) |
| Minecraft | 26.3 (protocol 777) — хост и гости обязаны назвать одну и ту же версию |
| ОС | Windows 10/11 x64 (тестировалось здесь; пути для Linux/macOS в коде есть, но их никто не запускал) |
| `steam_api64.dll` | **твоя, из твоей установки Steam** — лицензию Valve мы не вправе распространять |
| Друзья | хост и каждый гость состоят в друзьях в Steam, либо между собой передали код инвайта |

## Установка мода

**Когда мод появится в реестре Horizon** — самый простой путь: Horizon → **Mods** → выбери
инстанс → установи **e4steam** → **Build**.

**Из GitHub** (любой релиз этого репозитория, без ожидания реестра):

```sh
horizon-launcher mods add-github https://github.com/loldonres/e4steam_horizon_port \
  --mod e4steam --instance NAME --trust-native-code
```

**Из исходников этого репозитория**, если указать launcher'у на папку бандла:

```sh
horizon-launcher native-build horizon-mod/mixins/e4steam --instance NAME --trust-native-code
```

Все три пути приводят к одному: launcher скачивает собственный Rust, собирает игру с модом внутри
и ставит версию вида `native-<commit>-<key>`. Установленные нативные моды лежат в
`<instance>/horizon-native-mods/`. **Первая сборка занимает 20–30 минут**, дальше работает кэш.
`--trust-native-code` — это вопрос launcher'а *тебе*: доверяешь ли ты этому коду. Он специально не
предназначен для того, чтобы его подставлял скрипт или ассистент.

Удаление: сними мод на странице Mods (или `horizon-launcher mods remove e4steam`) и пересобери.

## Страница в меню паузы

**Esc → Options → Mods → e4steam → Settings.** Всё, что умеет мод, — это кнопки на этой странице, и
инструкция к ним не нужна:

| Кнопка | Что происходит |
|---|---|
| **раздать этот LAN-мир** | публикует мир, который ты уже открыл в LAN; порт мод находит сам |
| **подключиться к другу** | ждёт инвайт Steam — прими его в оверлее, и мод подключится |
| **доступ: друзья — нажми, чтобы изменить** | перебирает, кого пускать: друзья → по инвайту → для всех → только локально |
| **остановить раздачу** / **выйти из мира** | закрывает лобби, рвёт мосты, очищает presence |
| **показать код инвайта** | печатает код в чат — и напоминание, что код равен паролю |
| **прямое подключение 127.0.0.1:51234** | на странице гостя: адрес, по которому идти в Multiplayer |
| **e4steam · раздаю, гостей 2 из 7 — нажми, чтобы услышать подробности** | живое состояние, построчно в чате |
| **как этим пользоваться** | четыре шага в чате |
| **открыть это меню по-русски** | переключает подписи кнопок на русский — и обратно |

Страница следует за состоянием: пока мир раздаётся, строка доступа объясняет, что сначала нужно
остановить; если LAN-мира ещё нет, первая кнопка говорит об этом вместо того, чтобы молча
ошибаться. Кнопки перестраиваются при открытии страницы и после каждого нажатия.

`/steam` в чате — та же сессия для тех, кто предпочитает команды: расходиться они не могут, потому
что оба обращаются к одному и тому же потоку.

## Как быть хостом

1. Зайди в мир, нажми **Esc**, нажми **Open to LAN**.
2. **Esc → Options → Mods → e4steam → Settings → раздать этот LAN-мир** — или в чате `/steam host`.
3. Мод сам найдёт порт LAN-мира и опубликует Steam-лобби. Следи за строками в чате.
4. Нажми строку статуса — или `/steam status` — чтобы увидеть код инвайта,
   `s-xxxxxxxxx-yyyyyyyy.steam`.

Отдай этот код тем, кого пускаешь. **Относись к нему как к паролю: кто его знает, тот может зайти
в твой мир.** Не выкладывай его в публичные каналы, скриншоты и баг-репорты.

## Как зайти в чужой мир

1. Установи мод и собери, как описано выше.
2. **Esc → Options → Mods → e4steam → Settings → подключиться к другу** и прими его инвайт Steam —
   или в чате `/steam join s-xxxxxxxxx-yyyyyyyy.steam` (просто `join` ждёт инвайта,
   `join lobby <id>` принимает номер лобби).
3. Мод напечатает `127.0.0.1:<порт>`, а на страницы гостя есть кнопка **прямое подключение
   127.0.0.1:…**, которая повторит адрес. Открой **Multiplayer → Direct Connect** и введи его.

Другу на Java ничего лишнего от тебя не нужно: его e4steam делает ту же работу со своей стороны.

## Команды

У каждой из них есть кнопка на странице; флаги же доступны только из чата.

```
/steam host [--port N] [--access friends|invite|custom|local] [--discover MS] [--minecraft V]
/steam join [<код инвайта>|lobby <id>] [--port N] [--minecraft V]
/steam status
/steam stop
```

| Команда | Что делает |
|---|---|
| `host` | делится уже открытым LAN-миром; приглашения идут через Steam |
| `host --port 51234` | использовать этот порт вместо поиска по LAN-анонсу |
| `host --access friends` | кого пускать — см. таблицу ниже (по умолчанию `friends`) |
| `host --discover 15000` | дольше ждать LAN-анонс, максимум 60000 мс |
| `host --minecraft 26.3` | строка версии, которую гости обязаны повторить посимвольно |
| `join <код>` | подключиться к хосту; напечатает `127.0.0.1:<порт>`, куда идти |
| `join --lobby <id>` | зайти в известную лобби без кода |
| `status` | что сейчас работает, код инвайта и чего не хватает |
| `stop` | закрыть лобби, порвать мосты, очистить presence |

| `--access` | Значение |
|---|---|
| `friends` | только друзья Steam, состоящие в лобби, — безопасный выбор по умолчанию |
| `invite` | приватная лобби: пустят только того, у кого есть код инвайта |
| `custom` | публичная лобби со штатной проверкой членства в Steam; для экзотических схем |
| `local` | лобби не публикуется вообще; вход по коду напрямую |

До **7 гостей на хост**, 64 моста на процесс. Сообщения мода приходят в чат и они по-английски;
подписи кнопок на странице следуют языку, который ты там же и выбираешь.

Если вместо мода ты используешь sidecar: те же слова, только в консоли — `e4steam-rs.exe host`,
`e4steam-rs.exe join <код>`, `e4steam-rs.exe doctor` показывает dll, логин Steam, LAN-интерфейс и
анонс мира. Ctrl+C закрывает лобби и рвёт мосты.

## Что мод видит и что отправляет

Никакого скрытого сетевого доступа — но это *сетевой* мод, поэтому вот всё, к чему он прикасается.

- **Подключается к Steam** (к твоему же залогиненному клиенту), чтобы: прочитать список друзей,
  создать лобби или войти в него, обменяться токеном инвайта, передать игровой трафик напрямую
  пирам и поставить rich presence «играет с …», если выбрано `--access friends` или `custom`.
- **Пересылает трафик твоего LAN-мира** подключённым пирам; без сжатия, кроме мест, где протокол
  Java-мода требует zlib. Ничего другого с твоего компьютера не пересылается.
- **Слушает `127.0.0.1`**, чтобы игра могла туда подключиться; это loopback-сокет, а не публичный.
- **Читает LAN multicast-анонс** (`224.0.2.60:4445`), чтобы узнать порт мира.
- **Видит SteamID64 пиров** в лобби: так хост распознаёт друзей — ровно как в Java-моде. Сообщения
  в чат мод пишет с замаскированными SteamID, чтобы они не попадали в скриншоты.
- **Пишет два маленьких файла**: `steam_appid.txt` (одна строка `480` — тестовый AppID Steamworks,
  тот же, что у Java-мода) рядом с exe игры или в рабочем каталоге, и `e4steam/lang` в собственной
  папке настроек Horizon — одна строка, `en` или `ru`: язык, на котором ты оставил страницу.
  Удалишь файл — страница снова откроется по-английски.
- **Никакой телеметрии, аналитики, аккаунтов, паролей, чтения или загрузки файлов мира.** Ничего не
  улетает куда-либо, кроме как тем пирам, с которыми ты реально играешь.

## Не работает — куда смотреть

| Мод пишет в чате | Обычно это значит |
|---|---|
| `Steam is not usable: …` | Steam не запущен, не выполнен вход, или `steam_api64.dll` недоступна. Запусти Steam; при необходимости укажи `E4STEAM_STEAM_API` на полный путь к dll |
| `keep steam_api64.dll where the game finds it` | порядок поиска: `E4STEAM_STEAM_API`, папка рядом с exe игры, подпапка `steam/` рядом с ним, папки установленных игр в библиотеках Steam, затем обычный поиск Windows |
| `no LAN IPv4 address; open the world to LAN in Horizon` | ты ещё не нажал **Open to LAN**, либо у машины нет LAN IPv4-адреса |
| ничего про порт мира через несколько секунд | анонс не дошёл: передай `--port` с экрана LAN или подними `--discover` |
| `could not write steam_appid.txt` | каталог игры только для чтения; положи `steam_appid.txt` со строкой `480` рядом с exe сам |
| гость висит и потом сдаётся | хост не делится, код устарел, или `--minecraft` гостя не совпадает со строкой хоста |
| на странице первая кнопка читается **сначала открой мир в LAN, потом нажми** | Horizon ещё нечего раздавать: **Esc → Открыть в LAN**, затем нажми её снова |
| игра не стартует после сборки | мод закрепил коммит Horizon, на котором твой инстанс не играет, — см. [Закреплённые версии](#закреплённые-версии) |
| Windows Firewall спрашивает | разреши доступ игре; сам Steam P2P открытых портов не требует |

## Закреплённые версии

Нативный мод компилируется ровно против одного коммита Horizon — и это намеренно: он читает
приватное состояние LAN в самом Horizon, чтобы узнать порт мира, а это не стабильный публичный API.
На другом коммите сборка громко упадёт, а не соберёт наполовину сломанное.

| Закреплено | Значение |
|---|---|
| коммит Horizon | `aa27eca326db26e999d4e59d7899576016764b1e` (Nightly от 2026-10-31) |
| коммит horizon-mixins | `d9c83d7096b7ea5b83678da2efdfd6161f74997e` |
| Minecraft | `26.3` — protocol 777 |
| совместимый Java-мод | e4steam 0.3.2 / 0.3.4 |

Мод с пином собирается и после того, как его Nightly заменят: каждый Nightly навсегда хранит
исходники под тегом `nightly-source/<date>-<short>`. Если launcher отказывается — значит пин
работает как надо; заведи issue, и мы обновим его.

## Кросс-плей с Java-модом

| Что должно совпасть | Как |
|---|---|
| Версия протокола | кадр `E4ST`, байт версии `4`, виды сообщений, 12-байтная шапка |
| Лимиты кадров | чанки `DATA` по 32 КиБ, датаграммы 1188 байт, zlib только когда об этом говорит флаг |
| Строка версии | метаданные лобби `e4steam_minecraft` сравниваются посимвольно |
| Идентичность пира | SteamID64 берётся из сообщения Steam, а не из ника Minecraft |
| Инвайт | 16-байтный токен, проверка постоянным временем, максимум 7 гостей, дедлайн рукопожатия 30 с |

Гость с другой строкой версии отклоняется до всякого соединения — так же, как в Java-моде.
Побайтовой контракт, включая тайминги, описан в [`re/PROTOCOL.md`](re/PROTOCOL.md).

## Что внутри и чего пока нет

Сделано: кодек `E4ST` v4 (DATA/FIN/RESET/OPEN/OPEN_ACK/BRIDGE_READY, флаги и лимиты), Steamworks
**Flat API** без SDK и без C++ (`InitFlat` + manual dispatch, ISteamUser, ISteamFriends,
ISteamMatchmaking, ISteamNetworkingMessages на канале 480, лобби, rich presence, диалог инвайта),
мост localhost↔Steam (чанки 32 КиБ, backpressure на 2048 слотов с резервом 64 под терминальные
кадры, входящая очередь 256, ретраи отправки с hold-пакетом, отдельная очередь RESET из 10 попыток
с экспоненциальным backoff 25→2000 мс и джиттером, graceful close за 2 с), допуск на стороне хоста
с проверкой токена постоянным временем, разрешение адреса гостя через лобби и поиск порта LAN-мира
Horizon.

Не сделано:

- **Dedicated-серверы** через Steam (`SteamGameServer`, `DEDICATED_OPEN`, auth-тикеты) — спроектировано, но не дописано.
- **Голосовой чат** (Plasmo Voice) и **аддон-протокол** — сознательно вне объёма.
- **Подмена UUID игроков** (`e4steam:steam-identity:v1:`) — Horizon выводит offline-UUID из ника,
  поэтому друг сохраняет идентичность, только пока не меняет ник.
- **Живой тест на двоих в Steam** — у разработчика один Steam-аккаунт, поэтому сеанс «хост + гость»
  на настоящем Steam никогда не запускался. Всё остальное покрыто 104 автотестами на настоящих
  loopback-сокетах. Относись к первому заходу как к эксперименту и рассказывай, что сломалось.

## Сборка своими руками

```sh
cargo build --release                    # sidecar: target/release/e4steam-rs.exe
cargo test --workspace                   # 104 теста; второй аккаунт не нужен
python horizon-mod/tools/package.py      # -> horizon-mod/target/e4steam-<ver>.hnmod и его sha256
bash horizon-mod/tools/validate.sh       # настоящие horizon-mixins plan + apply на закреплённом исходнике
```

`validate.sh` только *подготавливает* модифицированные исходники через `horizon-mixins plan` и
`apply` — ничего не компилируется и не запускается, поэтому флаг доверия там не нужен. Компиляция
прошитого мода — это `horizon-mixins check` или кнопка **Build** в launcher'е, и её решает игрок сам.

Что где лежит — [`horizon-mod/README.md`](horizon-mod/README.md) подробно объясняет бандл и шесть
впрысков (три для чата, три для страницы):

```
horizon-mod/mixins/e4steam/   бандл .hnmod: манифест, injectable payload, хелперы
                    engine/    общий движок: кодек E4ST, Steamworks, мост, /steam
horizon-mod/check/             мок геометрии Horizon, чтобы cargo test проверял типы мода
horizon-mod/tools/             package.py (воспроизводимый архив), validate.sh (правила реестра)
cli/                           бинарник sidecar
re/                            спека протокола, декомпилированный Java-оригинал, документация Horizon — не поставляется
```

### Перед подачей в реестр

Проверяющий смотрит, что заявка полна, файлы совпадают с закреплёнными хэшами, мод собирается и
загружается против названной версии Horizon и в нём нет очевидно вредного. Этому репозиторию ещё
нужны три вещи:

1. **Не держать сборки в git.** `target/` и `horizon-mod/target/` — сгенерированное; `.hnmod`
   принадлежит **релизу на GitHub**, а не дереву исходников.
2. **Не публиковать `re/decompiled/` и `re/ref/`.** Там декомпилированные классы оригинала и нативные
   библиотеки, упакованные внутрь эталонного JAR, включая `steam_api64.dll` от Valve — из-за них же
   фраза в `NOTICE.md` «not shipped with this source tree» становится неправдой, пока эти файлы в
   репозитории. Если хочется оставить контракт на странице, хватит `re/PROTOCOL.md` — он написан нами.
3. **Одинаковые сведения везде.** В заявке реестра нужны: автор, ссылка `source` на код, из которого
   собран опубликованный файл, лицензия Apache-2.0, поддерживаемая версия Horizon выше и ссылка на
   <https://github.com/Kamilhik/e4steam> с указанием автора — потому что это порт.
